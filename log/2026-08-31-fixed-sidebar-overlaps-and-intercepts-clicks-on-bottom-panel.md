## What happened

Building Phase 4's Output panel and its new Terminal/Output tab strip
(`src/workbench/shell/workbench.jac`), live browser verification (`jac browse` against a real
`jac run --serve --dev` process) found the new tab labels ("Terminal", "Output") completely
invisible in a screenshot despite the accessibility tree, computed styles, and bounding-rect checks
all reporting them present, correctly colored, and `visible: true`.

Worse than cosmetic: a synthetic click at the real on-screen coordinates of the (pre-existing)
Terminal panel's own header label failed with `not actionable: point (23,547) is covered by div`
during an earlier PR's verification pass (toast notifications) -- at the time worked around with a
raw `elementFromPoint` + synthetic `MouseEvent` dispatch, without yet knowing *why* the real click
target was unreachable. Building this PR's second tab made the same gap concretely visible and
worth root-causing properly instead of routing around it a second time.

## Root cause

```js
document.elementFromPoint(50, 495).outerHTML
// -> <div data-radix-scroll-area-viewport ... > (the file-tree sidebar's own ScrollArea)
```
Walking the ancestor chain of that element found the actual culprit five levels up --
`components/ui/sidebar.jac`'s vendored desktop wrapper (generated by `jac install --shadcn
sidebar`):

```
class="fixed inset-y-0 z-10 hidden h-svh w-(--sidebar-width) ..." (Tailwind: position: fixed;
top/bottom: 0; height: 100svh; z-index: 10)
```

`inset-y-0` + `h-svh` makes this element span the **entire viewport height**, not just the visual
column above wherever the app's own layout happens to place a bottom-docked panel -- entirely
correct behavior for a typical single-scroll-region sidebar layout (which is presumably all the
generator was designed against), but jac-studio's workbench also has a bottom panel (Terminal/
Output) docked below the sidebar's own visible content, occupying the same horizontal 256px column.
Because the fixed sidebar wrapper has `z-index: 10` and the panel's own container was a plain
`position: static` flow element with no z-index, the sidebar painted (and intercepted pointer
events) **above** the panel's leftmost 256px in every case, regardless of the two elements' visual
vertical order in the actual layout. This is not new to this PR -- the single pre-existing
"Terminal" header label had the exact same defect the whole time, just with no second interactive
element in that column to turn "text is invisible" into an obviously-broken click.

## Fix (shipped)

`position: relative; zIndex: 20` on the bottom-panel's own outer container in `workbench.jac` --
establishes a stacking context above the sidebar's `z-index: 10`, without touching the vendored
`Sidebar` primitive itself (a hand-patch there would be silently reverted by any future
`jac install --shadcn sidebar` regeneration, the exact same regeneration pitfall Phase 3's
`2026-08-28-shadcn-command-generator-missing-root-wrapper`-style findings already hit for other
primitives). Confirmed fixed live: both tab labels render and are independently clickable at their
real screen coordinates (no synthetic-event workaround needed), verified via a fresh `jac browse`
screenshot and a genuine `elementFromPoint` check landing on the tab button itself.

## Plan

`resolved`, not `workaround-found` -- an app-level `position`/`z-index` on the app's own layout
container is the normal, permanent way to win a stacking fight against a third-party component's
`fixed` element; nothing here is a stopgap pending an upstream jaseci/shadcn-generator change.

Worth checking, not yet done: the notification-center bell mounted in `status_bar.jac` (a separate,
still-unmerged Phase 4 PR) sits in the same status-bar row immediately below this panel, inside the
same 256px-wide sidebar column when the sidebar is present -- it should get the same
`position: relative` treatment (or inherit a shared one) if its own Sheet trigger turns out to have
the identical click-interception problem; not yet verified against this specific finding since that
PR was written before this root cause was known. Flag for whoever reviews/merges it next.
